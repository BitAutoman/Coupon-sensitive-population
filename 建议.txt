这样删东西会非常容易。

### 一、训练 Review：你的两个修改我都赞成

当前实验表是：

`实验 / ROC-AUC / PR-AUC / Lift@1% / Lift@10% / 最佳轮数`。

这里建议改为：

| 实验 | ROC-AUC | AP | Precision@1% | Lift@1% | Lift@10% |
| -- | ------: | -: | -----------: | ------: | -------: |

其中：

1. **PR-AUC 改成 AP**

   因为代码实际计算的是 `average_precision_score`，所以 Review 应该和代码口径完全一致。不要再混用 PR-AUC。

2. **最佳轮数删除**

   `best_iteration=119/296/258` 属于模型训练细节，不是判断 E3/E4/E5 谁更好的核心指标。它应该留在 metadata/checkpoint 中，不需要出现在结果总览。

我还建议增加 **Precision@1%**。因为现在结论里已经写了“Top 1% 实际命中率 80.1%”，但表格里却看不到这个数。

对非算法同学来说：

> Top 1% 用户中，80.1% 是正样本

比单独看到：

> Lift@1%=11.17

更容易理解。

# 七、训练 Review 和 Test Review 最后最好形成这种对应关系

我建议最终非常简单：

| Training Review     | Test Review         |
| ------------------- | ------------------- |
| **选哪个模型？**          | **选好的模型泛化怎么样？**     |
| E0～E5 对比            | Validation vs Test  |
| AP / ROC-AUC / Lift | AP / ROC-AUC / Lift |
| 为什么 E5 最好           | E5 在未来时间是否稳定        |
| 十分位排序               | Test 十分位排序          |
| 特征重要性               | Unseen Users        |
| 冻结 E5               | 最终结论                |

这样第一次做模型的同学看完会自然形成：

```text
Train
  ↓
训练 E0～E5
  ↓
Validation
  ↓
对比 AP / ROC-AUC / Lift
  ↓
选择 E5
  ↓
Freeze
  ↓
Test
  ↓
检查时间泛化 + Unseen 泛化
```

这其实才是你的 Review 最应该传递的东西。

另外还有一个现在已经过期的小地方：训练 Review 结论第 4 条还写着 **“正式 Test 尚未用于本轮最终报告”**。 如果 Training Review 是当时冻结时生成的历史快照，可以保留；如果你准备让它作为现在项目的最终入口页，建议改成：

> **Validation 已完成选模并冻结 E5；最终 Test 结果见 Test Review。**

总体上，我会把两个 Review 都控制在**“打开后 30 秒能知道结论，3 分钟能知道为什么”**这个程度，而把调参、校准、文件路径、底层 CSV 都下沉到附录。
